# MTProto-юзербот вместо Bot API

Читаемая группа не принадлежит нам (её адрес задаётся в `.env`, в репозитории его нет), добавить в неё бота-админа нельзя, поэтому Bot API отпадает. Читаем её через MTProto-клиент (`gotd/td`) от лица отдельного выделенного аккаунта: один раз интерактивный вход (код, при наличии — 2FA), сессия живёт на volume, аккаунт вступает в группу вручную, сервис раз в 30 секунд опрашивает историю группы (`messages.getHistory`) и пересылает совпадения получателю тем же аккаунтом.

## Последствия

- Нужны `api_id`/`api_hash` с my.telegram.org и одноразовый вход с кодом (и паролем 2FA, если он есть).
- Членство в группе обязательно для live-апдейтов мегагруппы и делается человеком; сервис проверяет его при старте и падает с внятной ошибкой, если его нет.
- Аккаунт-юзербот виден как отправитель форвардов, автор объявления — в шапке форварда.
- Аккаунт может получить ограничения за автоматизацию. Риск снижаем: только чтение, без постинга, вступления и любых массовых действий.
- Апдейты (`updateNewChannelMessage`) не используем: опрос истории сам закрывает пропуски после реконнекта, рестарта и простоя, а цена — до `POLL_INTERVAL` задержки на объявление (при 500–1000 сообщениях в сутки это неважно).
